## Why this packet exists

Bank data is F2, and ARCHITECTURE.md's Stage 5 exit is *"sandbox connect → categorised transactions
→ plan with concrete tradeoffs. The demo video."* Everything behind that sentence is built and
tested — link token, public-token exchange, encrypted storage, cursor sync, transfer pairing, the
recurring streams, webhook translation, and the planning side that prices a plan from the ledger.

**None of it is reachable.** P3 built `IngestionService` with no HTTP, which its brief did not ask
for. P6's build list names every route except these. P8's loop runs signup → city → income →
dashboard with no "connect your bank" step. No brief ever said who exposes it, so nobody did. This is
the same gap P6 found for F8 and F9 — built, tested, impossible to use — and it was not caught here.

## Build

**Four routes, all thin.** The service methods already exist; this is assembly.

| Route | Calls | Notes |
|---|---|---|
| `POST /api/v1/bank/link-token` | `startLinking(userId)` | Returns the token for Plaid Link. |
| `POST /api/v1/bank/connections` | `connect(userId, publicToken)` | Returns at once; the import runs on the executor, never on the request. |
| `GET /api/v1/bank/connections` | `connections.forUser(userId)` | Institution name and last sync. **Never** the token, encrypted or not. |
| `POST /api/v1/bank/connections/{id}/sync` | `requestSync(id)` | Only after the ownership check below. |

**The ownership check is the part that matters.** `BankConnections.find(id)` and
`IngestionService.requestSync(id)` take a bare connection id and are not scoped by user; that was
right for a service only webhooks called. A route that passes a path id straight through lets any
signed-in user trigger a sync of someone else's bank. Resolve the connection through
`forUser(userId)` (or add a user-scoped `find`) and answer a connection that is not theirs exactly as
one that does not exist — `ApiProblems` already promises that ids cannot be probed.

**`connect` throws an `IllegalArgumentException` naming the Plaid item id** when the item belongs to
another account. `ApiProblems` renders that message to the user verbatim, which both leaks an
identifier and breaks packet rule 10. Give it its own exception and a sentence a person can act on.

**Client.** A "Connect your bank" step reachable from onboarding and from the money page, using
Plaid Link (`react-plaid-link`, or Plaid's script with a typed wrapper). The bank login is typed into
Plaid's widget and never into our page — that is the trust claim in ARCHITECTURE.md §10, so say it
on screen in plain words. After connecting, show that the import is running and refresh the plan
when it lands rather than asking the user to reload.

## Webhooks — second, and only if a public URL exists

Plaid cannot reach `localhost`, and syncs already happen when the user opens the app, so webhooks
are not needed for the demo. If you add `POST /api/webhooks/plaid`:
- it is the **one** gateway route that skips Supabase auth; make it exact-path, not a prefix;
- **verify the `Plaid-Verification` JWT** (ES256, key from `/webhook_verification_key/get`, body
  SHA-256 matching, issued within five minutes) before `PlaidWebhookTranslator` sees the body. An
  unverified webhook endpoint lets anyone make us call Plaid on any item id they can guess.
