## Scope, and what was deliberately cut

This packet stores and resolves city cost figures. It does **not** derive them from government
statistics — the BLS/BEA/Census pipeline was cut before anything was written, and is fully specified
in `.claude/packets/P9-DEFERRED-official-cost-of-living.md` for later.

You are building the **curated** version: a small hand-entered set of cities, plus the resolution
machinery that a future official source will plug into without touching a caller.

**Do not build:** an ingestion tool, API clients, a scheduled refresh, or anything reading BEA, BLS or
Census. If you think you need one, you have misread the scope — stop and report.

## Build

1. **The Postgres schema**, as Flyway V1–V9: `country`, `metro_area`, `data_source`,
   `city_category_baseline`, `city_contribution`, and the user override tables. Full shape in
   `ARCHITECTURE.md` §8.

   **`city_category_baseline.income_quintile` MUST be nullable.** Curated rows have no quintile;
   a future BLS-derived source does. Making it `NOT NULL` — including as part of a composite primary
   key — means the deferred pipeline needs a migration and a backfill later. This one column is the
   difference between that feature being a new class and being a schema change. Use a surrogate key
   with a partial unique index rather than folding a nullable column into a primary key.

   `@Enumerated(EnumType.STRING)` and `TEXT` columns always — an ordinal column plus a later enum
   reorder is silent data corruption, and ArchUnit enforces it.

2. **Curated seed data**, as a committed CSV under `resources/data/` loaded by a Flyway migration.
   Roughly ten cities is plenty:
   - **Lebanon** — Beirut, Tripoli, Sidon, Zahlé, Jounieh, Byblos. Confidence `CROWDSOURCED`, in
     **USD**: Lebanon has been de facto dollar-priced since 2019, so no FX layer is needed. Give every
     row an explicit `as_of`.
   - **A few US metros** for contrast — San Francisco, New York, Wichita, Austin. Confidence
     `CROWDSOURCED` too, since these are curated rather than derived. **Do not label anything
     `OFFICIAL`** — that tier is reserved for genuinely derived data, and mislabelling it is the one
     failure that would make the whole confidence model dishonest.
   - Country-level `ESTIMATED` rows for `US` and `LB`, used as the fallback layer and to pre-fill the
     manual form.

3. **`BaselineResolver` as an ordered list of layers**, not nested ifs:
   user override → `OFFICIAL` → `CONTRIBUTED` → `CROWDSOURCED` → country `ESTIMATED`.
   **Leave the `OFFICIAL` layer in place even though nothing populates it** — that empty slot is where
   the deferred pipeline lands. Adding a source must be appending one layer.

4. **Two provider implementations, one contract.** `JpaCostOfLivingProvider`, and
   `ClasspathCostOfLivingProvider` reading the same committed CSVs. Both must pass **the same shared
   abstract contract test**. That test costs almost nothing and is the proof the port is honest rather
   than decorative; the classpath one also keeps every pure domain test runnable with no database.

5. **Staleness derived, not hardcoded.** `drift = annual_inflation × age_months / 12`; FRESH under
   5%, AGING to 15%, STALE beyond. Same code, opposite behaviour per country: the US at ~3%/yr stays
   fresh 20 months, Lebanon at 17.3% goes stale in ~10. **Never auto-inflate a stored figure** — that
   fabricates precision. Offer the adjusted number as a pre-filled default the user confirms, at which
   point it becomes `USER_PROVIDED`.

6. **The cascading catalogue endpoints** — countries, then that country's cities, each carrying
   confidence and `as_of`. A user-typed `city_label` is **display-only and never a lookup key**, which
   removes geocoding and fuzzy matching entirely: a typo can never almost-match the wrong metro. The
   manual form is **pre-filled** from the country `ESTIMATED` layer — eleven blank boxes is where users
   abandon signup.

7. **The contribution pipeline.** A user's figure is private to them on write, and becomes a city
   default only after passing validators **and** explicit approval. Bank corroboration is the
   validator that matters, because it is the only one that works with a single user: it checks a claim
   against that person's own transactions rather than against opinion. Quorum and MAD outlier
   rejection are designed but not built — say so in the README rather than implying a live
   crowdsourcing network exists.

JPA entities never escape `costofliving/persistence`.

## Honesty requirement

The curated numbers are researched estimates, not statistics. Label them `CROWDSOURCED`, give them a
real `as_of`, and state plainly in the README that v1 ships curated figures for a handful of cities
with the official pipeline deferred. The product's main claim on user trust is that it never dresses a
guess up as a fact — that applies to its own documentation too.
