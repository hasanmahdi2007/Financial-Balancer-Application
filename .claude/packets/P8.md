**You own:** `client-portal/**`. Node v24.19.0 is already installed.
**Wave:** 4, after P6 has merged.

---

Build the full loop, because the product is only legible visually:

signup → country dropdown → city dropdown, or **"my city isn't listed"** → pre-filled manual form →
income and lifestyle tier → considered share of the balance → dashboard → add a goal → watch the
recompute and the tradeoffs → add a competing higher-priority goal → watch the re-ranking.

**Render provenance everywhere a number came from data**: the confidence badge, the `as_of` date, and
the staleness banner when a figure has drifted. The user should always know whether they are reading
a government statistic or an estimate — that honesty is the product's main claim on trust, and hiding
it would make every other number look equally authoritative.

**Render the words the API sends, never the constant name.** An earlier draft of this brief listed
`OFFICIAL`, `CONTRIBUTED`, `CROWDSOURCED`, `ESTIMATED`, `USER_PROVIDED` as the badge text. Do not do
that — it contradicts packet rule 10, and it is not what the API returns anyway. Each city carries
`basis` ("Researched by us") and `explanation` ("We gathered this from listings and local prices. It
is a careful estimate, not an official statistic."). `CROWDSOURCED` is an internal word, and a person
asked to judge a figure labelled with it is being asked to guess.

The wording lives on the `Confidence` enum beside the behaviour, so a new tier cannot ship without
one, and `CatalogueEndpointIT` asserts that no constant name reaches a payload. **Do not build a
label map in TypeScript** — it would be a second copy of that policy and would drift the first time a
tier is added.

The "my city isn't listed" form must arrive **pre-filled** from the country estimate. Eleven blank
boxes is where users abandon signup.

## Signing the user in is yours, and no other brief says so

The loop above starts with **signup**, and nothing else in this project can perform it. P6 builds the
gateway that *verifies* a Supabase token; **producing** one happens in a browser, so it belongs here.

**Keys you need:** `SUPABASE_URL` and `SUPABASE_ANON_KEY` from `.env`. The anon key is a publishable
client key and is the only Supabase credential that may appear in browser code. `SUPABASE_JWKS_URI`
is the gateway's, and a service-role key must never be committed or bundled.

What this packet owns:

- sign-up and sign-in against Supabase, using `@supabase/supabase-js`;
- holding the session and refreshing it before it expires;
- sending the access token on every request to the gateway;
- handling a rejected or expired token by returning the user to sign-in, rather than rendering a
  dashboard full of empty state that looks like a data bug.

**The Supabase project itself is created in P6**, which is part of why this packet is Wave 4. If you
arrive here and no project exists, stop and ask. Do not invent an auth stub to get moving — a fake
login that later has to be unpicked from every screen costs more than the wait.

> This section was added after the fact, because it was missing. Every other packet names the keys it
> needs; this one named none, even though `.env.example` has reserved `SUPABASE_ANON_KEY` since P0 —
> a key only a browser ever uses. Nobody had written down who signs the user in. Finding that out in
> Wave 4, with the whole client already built, would have been an expensive surprise.

## What already exists for you

The cascading picker is built and covered by tests, so do not re-derive it:

- `GET /api/catalogue/countries` → `{code, name, note}`. `note` is the caveat a user needs before
  trusting the figures — for Lebanon, that prices are quoted in US dollars.
- `GET /api/catalogue/countries/{code}/cities` → `{id, name, region, basis, explanation, gathered}`.
  `id` is the slug, and it is the **only** lookup key there is: a typed city name never resolves to a
  city, which is what removes fuzzy matching from the product. Send back the `id` the user picked.
- `GET /api/catalogue/countries/{code}/manual-form` → one `{question, why, covers, suggested, basis}`
  per category, already pre-filled from the country estimate.

`covers` arrives as rendered lines such as `"Rent - your rent or mortgage payment"`, assembled from
the category table rather than written by hand. Render those strings; do not compose your own copy
for them, for the same reason you should not build a label map.
